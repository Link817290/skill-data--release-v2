# Business workbooks that can be read and audited

Inspect actual business worksheets relevant to the task before choosing a style. Distinguish a summary form, a budget comparison and a long operational ledger. They need different widths, row heights and print treatment; applying one default layout to every sheet makes a workbook look like a database dump.

Place a meaningful table title, reporting period and units above the table. Use grouped headers only when they accurately describe the columns underneath. A cost column should not sit under a service-performance heading merely to balance the layout. Keep data rows unmerged so filters and sorting remain usable.

Align numeric columns by magnitude, use consistent currency precision, retain identifier leading zeros and distinguish blanks from genuine zeros. Subtle vertical rules prevent adjacent right-aligned numbers from reading as one number. Reserve emphasis for a recommendation or actual exception; do not color every row as if it were a dashboard.

For machine-coded fields, readable labels can be displayed while retaining canonical values, but the mapping must be explicit and verified in the actual spreadsheet application. Do not mistake a display-format change for a data transformation. Keep a before/after comparison of cell values and formulas when styling an existing workbook.

Exercise printing separately from on-screen navigation. Freeze identifying columns, repeat headers on continuation pages and retain identifiers when wide tables split horizontally. A merged heading or note overlapping repeated columns can be clipped on every continuation page; keep that content outside the repeated columns or use a concise page header.

Render a disposable copy through the target spreadsheet application. Some applications modify workbook metadata even during nominally read-only export. Confirm the delivered file's hash is unchanged by inspection. Review summary sheets and representative continuation pages, and label sampling honestly: rendered first rows do not establish readability of every row in a long ledger.

Use programmatic checks for values and inspect the saved workbook for clipping, units and table usability. Compare the meaning of conclusions with the verified tables. Keep the inspection scope clear; a styling script finishing successfully does not establish that a decision-maker can read the result.
