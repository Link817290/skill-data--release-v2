## 一、确认冲突（10 处）

### C01　同一芯片的算力取值冲突

- 位置：`1.2 解决方案框架` 表（芯片类型 / 算力(TOPS) / 功耗(W) / 典型延迟(ms)）与 `2. 芯片厂商的算力支持` 表（芯片类型 / 算力(TOPS) / 功耗(W) / 能效比(TOPS/W)）
- 冲突：`通用GPU` 的算力，前表记 **200 TOPS**，后表记 **250 TOPS**
- 判定依据：两表的功耗同为 300W，排除了「两表指不同型号」的解释。后表内部自洽（250 ÷ 300 = 0.83，与其能效比列一致），故前表的 200 为离群值
- 影响：算力是全文选型论证的起点，两个值会导出不同的能效结论

### C02　权重列合计不足 100%

- 位置：`5.1 联合实验室与测试平台` 表（测试维度 / 分级标准 / 权重）
- 冲突：三行权重为 30% + 25% + 20% = **75%**，缺 25%
- 判定依据：该列为权重，按定义应合计 100%。同文档 `3.1`、`4.1`、`7.2`、`13.1` 四张权重表均为 30+25+20+15+10 = 100%，构成文档自身的口径证据
- 影响：无法据此表计算综合测试得分。要么漏写一个维度，要么现有权重需重新分配

### C03　同一张表混用两种百分比口径

- 位置：`4. 行业应用方的场景落地` 表（指标 / 传统方法 / AI系统 / 提升幅度）
- 冲突：
  - `检出率` 82% → 95%，提升幅度记 **13%**，即 95 减 82 的**百分点**差
  - `假阳性率` 35% → 12%，记 **-23%**，同为百分点差
  - `阅片速度` 15 → 60，记 **300%**，是 (60-15) ÷ 15 的**相对**增幅
- 判定依据：同一列的三行使用了两种互不相容的计算口径。若统一用相对口径，检出率应为 15.9%；若统一用百分点，阅片速度应为 45
- 附带问题：`假阳性率` 下降是改善，列名为「提升幅度」却记为负值，读者会误读为劣化

### C04　故障响应时限在两张表及同节正文中冲突

- 位置：`10. 持续运营与技术支持` 表（问题等级 / 响应时间 / 解决时限 / 升级条件）与 `10.2 故障排查与维护` 表（故障等级 / 响应时间 / 团队组成 / 升级路径）
- 档位对齐依据：两表均为三档，且描述可逐档对应。`常规` 的升级条件为「非阻塞性功能异常」，`P2` 为「非关键异常」，指同一档
- 冲突：

| 档位 | 前表响应时间 | 后表响应时间 | 是否一致 |
|---|---|---|---|
| 紧急 / P0 | 15分钟 | ≤15分钟 | 一致 |
| 高 / P1 | **1小时** | **≤30分钟** | 冲突 |
| 常规 / P2 | **4小时** | **≤2小时** | 冲突 |

- 判定依据：`紧急 / P0` 一致，证明两表确为同一套 SLA 的两次表述，排除了「两套独立体系」的解释
- 同节正文佐证：`10.2 故障排查与维护` 节首的故障分级正文（后表 T66 所在小节的上级节，P1357 至 P1359）写「P0级（致命故障）…需15分钟内响应」「P1级（严重故障）：部分功能降级，响应时效1小时内」。P0 与两表一致；P1 的 **1小时内** 与前表一致，与后表 **≤30分钟** 冲突，说明后表为离群。正文 P2 级写「8小时内处理」，是处理时限而非响应时间，不与表中响应时间比较
- 影响：SLA 是对外承诺条款，两个版本会直接引发履约争议

### C05　同一案例的延迟要求冲突

- 位置：`4.2 解决方案设计与验证` 的验收阈值表与测试指标表
- 冲突：制造业案例的推理延迟，前者记 **<500ms**，后者记 **200ms内完成产线图像分析**
- 判定依据：产线图像分析包含推理环节。若全流程须在 200ms 内完成，推理不可能获准占用 500ms。二者不可同时成立，不是口径差异

### C06　通用大模型的延迟区间与同节实测值冲突

- 位置：`3.1 模型选型与定制` 的选型评分表（含 推理速度(ms) 行）与同节的通用与专用模型对比表（含 推理延迟（毫秒） 行）
- 冲突一：对比表称通用大模型为 **800-1200ms**，而同节评分表列出的三个通用大模型实测为 LLaMA-2-70B **420**、GPT-3.5-Turbo **180**、Claude-2 **210**，**无一落入该区间**
- 冲突二：对比表称行业专用模型为 **200-500ms（经优化后）**，而同节评分表的行业专用模型为 **150ms**，同样在区间外
- 判定依据：两表同在 `3.1` 节，所列模型即为对比表所称的两类。两处冲突互相独立

### C07　由非数值取值给出百分比提升

- 位置：`9.2 金融行业` 表（指标 / 传统模式 / AI模式 / 提升幅度）
- 冲突：`客户覆盖率` 行的传统模式为「高净值」、AI模式为「全客群」，提升幅度记 **300%**
- 判定依据：两个输入单元格均为文字描述，不含可计算的量，300% 无推导路径。同表另两行（服务响应速度 48小时 → 20分钟 = 144倍，组合收益率 6.2% → 8.1% = 30.6%）均可由本行数值复算，构成对照

### C08　成本模型表的总拥有成本与引导句给出的部署规模不符

- 位置：`2.1.2 边缘计算芯片（如FPGA、ASIC）` 表 T7（芯片类型 / 单芯片成本 / 开发成本 / 总拥有成本（5年）），引导句 P290「成本模型示例（以10K节点部署计）：」
- 冲突：
  - `ASIC` 行（第 2 行）：$150 × 10,000 + $200K = **$1.70M**，表记 **$1.7M**，一致
  - `FPGA` 行（第 1 行）：$220 × 10,000 + $80K = **$2.28M**，表记 **$3.2M**，差 $0.92M
- 判定依据：同一列、同一部署规模，ASIC 行按「单芯片成本 × 节点数 + 开发成本」恰好成立，FPGA 行按同一口径不成立。「5 年 TCO 另含运维」的读法无法解释 ASIC 行没有任何运维成分；同节正文 P283 称「ASIC需6个月以上但后期维护成本低30%」，也推不出只有 FPGA 额外多出 $0.92M
- 影响：两种芯片的成本差距被夸大为 $1.5M（按表）而非 $0.58M（按复算），直接影响边缘芯片选型的成本论证

### C09　引导句声明的层数与表格行数不符

- 位置：`7.2.1 GDPR等法规遵从` 表 T44（合法性依据 / 验证方式 / 文档要求），引导句 P985「数据处理合法性基础　建立六层合规验证机制：」
- 冲突：引导句称 **六层**，表中只有 **3 行**：`用户明确同意`、`合同履行必要`、`法律义务`
- 判定依据：引导句以冒号直接引出本表，未使用「例如」「包括但不限于」等示例性措辞，表格应完整列出所称的六层
- 影响：合规验证机制缺三层，对外呈现的合规框架不完整

### C10　「满分10分」评分表中混入原始计量值

- 位置：`3.1 模型选型与定制` 表 T12（评估维度 / 权重 / LLaMA-2-70B / GPT-3.5-Turbo / Claude-2 / 行业专用模型），引导句 P366「候选模型评估矩阵　建立量化评分表（满分10分）横向对比开源与商用模型：」
- 冲突：五行中只有 `任务准确率`（8.2 / 9.1 / 8.7 / 9.4）是 10 分制得分。其余各行：
  - `推理速度(ms)`：420 / 180 / 210 / 150，为毫秒原始值
  - `微调成本($/epoch)`：6,500 / N/A / N/A / 3,200，为美元原始值
  - `多模态支持`：否 / 是 / 部分 / 是，为文字
  - `领域知识覆盖`：通用7.5 / 通用8.3 / 通用8.0 / 专业9.8，数值前附文字
- 判定依据：引导句明确为「满分10分」的量化评分表，并配有合计 100% 的权重列；420、6,500 等值超出 10 分满分，文字值无法加权，按权重计算综合得分不可行
- 影响：选型评分表无法得出综合分，横向对比结论无依据

## 二、需作者确认（10 处）

以下 10 处存在差异，但均有合理的另一种读法，不宜直接判为错误，交作者确认。

### U01　肺结节相关指标差异

`9.1 医疗行业` 的两张表分别给出 `肺结节检测` 准确率 98.2%，与 `肺部微小结节` AI辅助检出率 94%。一为准确率一为检出率，且「微小结节」范围窄于「结节」，可读作两个不同口径而非冲突。

### U02　端侧推理延迟目标差异

`8.1 边缘端模型部署` 的目标阈值为 `推理延迟 <100ms（端侧）`，`12.2 开发者社区建设` 的目标值为 `推理延迟 <50ms（边缘设备）`。前者为部署验收规范，后者为框架优化目标，可读作不同层级的指标。

### U03　收益分配比例差异

`11. 商业模式与收益分配` 表给出技术提供商 50%-70%、数据合作方 15%-30%、渠道合作伙伴 5%-10%、平台运营方 10%-20%；`11.1 合作模式设计` 表给出 AI技术供应商 45%、行业客户 30%、系统集成商 25%。技术方的 45% 低于前表区间下限，系统集成商的 25% 不落入前表任一档。

但前表列名为「分配比例（示例）」，且两表的参与方分类并不相同（后表的「行业客户」不等于前表的「数据合作方」，且后表无「平台运营方」）。将两表对齐本身即是推断，故列为存疑。

### U04　GPU 能效比差异

`2.2 算力优化与部署` 表记 `GPU` 能效比 5-8 TOPS/W，`2. 芯片厂商的算力支持` 表记 `通用GPU` 能效比 0.83 TOPS/W，相差约 7 倍。

但两表的行标签不同，且峰值算力区间（20-50 TOPS 与 250 TOPS）不重叠，可读作两类不同档次的设备。

### U05　案例阈值宽于同节基准要求

`4.2 解决方案设计与验证` 的基准要求表（指标类型 / 基准要求 / 行业标杆参考）记 `推理速度 ≤200ms/请求`，而同节验收阈值表的两个案例阈值为制造业 <500ms、金融风控 <300ms，均宽于基准。

但验收阈值表是 2-4 周 MVP 概念验证的指标，基准要求表属于性能评估与迭代阶段，「验证期阈值宽于迭代期基准」可以成立。同节 `模型准确率` 基准 ≥92% 与验收阈值表的 `精确率` ≥92%、≥98% 不是同一指标，不能作为同表对照。故列为存疑。

### U06　边云决策表延迟行存在未覆盖区间

`8. 边缘计算与云端协同` 表（决策因子 / 边缘倾向条件 / 云端倾向条件）的 `延迟要求` 行为边缘 <200ms、云端 ≥1s，200ms 到 1s 之间未写明倾向。

但表头为「倾向条件」而非划分规则，同表 `隐私等级` 行（需本地脱敏 / 可加密传输）同样不是完整划分，中间区间可理解为由其他因子决定。故列为存疑，建议作者补写或说明。

### U07　权限分级缺中间档

`7. 数据安全与隐私保护` 表（权限等级 / 数据范围 / 操作权限 / 审计频率）仅列 L1 与 L3，未列 L2。

命名推断 L2 存在，但表前写的是「典型配置如下」，可能只列两端示例；本条无对照表支撑。两档跨度（脱敏数据只读月度审计 → 原始数据读写实时审计）较大，建议作者确认是否补 L2。

### U08　同一模型同一显卡的基线延迟差异

`6.2.1 低延迟优化` 表 T37 第 1 行 `原始模型` 延迟 **23ms**（引导句 P840 写「ResNet50在T4显卡上通过TensorRT优化后，延迟从23ms降至9ms」）；`10.1 模型迭代与升级` 表 T61 第 1 行 `FP32原版` 延迟 **45ms**（引导句 P1307 以 ResNet50 与 NVIDIA T4 为例）。同为 ResNet50 在 T4 上的未优化基线，相差近一倍。

但两处均未给出 batch size 与测试条件，且 P1307 写的是「目标硬件（如NVIDIA T4）」，T61 未必在 T4 上测得。故列为存疑。

### U09　引导句倍数与配置表比值不完全吻合

`2.2.1 芯片级性能优化` 引导句 P311 写「NPU专用于矩阵运算，处理效率较通用CPU提升8-12倍。典型配置如下表」；表 T9 中 `NPU` 峰值算力 50-100 TOPS、`CPU` 2-5 TOPS，比值为 10 至 50 倍；能效比 15-30 与 0.8-1.2 TOPS/W，比值为 12.5 至 37.5 倍。

两个比值区间与 8-12 倍只在 10 至 12 倍处重叠，但「处理效率」未说明按算力还是能效计算，也可能指典型负载下的实测值。故列为存疑。

### U10　同节正文的漏诊率降幅与检出率表不符

`9.1.1 医学影像分析` 节首正文 P1193 写「算法敏感度可达95%以上，特异性超过90%，有效降低漏诊率5-8个百分点」；同节表 T55 三行的 AI 辅助检出率提升为：`肺部微小结节` 72% → 94%（22 个百分点）、`脑出血` 85% → 97%（12 个百分点）、`乳腺钙化` 68% → 91%（23 个百分点），对应漏诊率降幅均远超 5-8 个百分点。

但正文所举病种为「肺结节检测、脑卒中病灶分割、骨折定位等」，与表中病种不完全相同，正文可读作一般场景的典型值、表格为特定难例。故列为存疑。
