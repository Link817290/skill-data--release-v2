# Getting evidence out of engineering sources

A tender deliverable is only as defensible as the trail behind it. The work here
is not "read the documents" but "turn each document into identified facts that
still carry where they came from". Three things go wrong most often: a format
that looks unreadable is quietly skipped, a document is read in the wrong place
so its values are never found, and a fact arrives in the deliverable with its
origin lost.

## 1. Inventory before extracting

List every supplied file with its type and what it is authoritative for. A scope
note is authoritative for contract boundaries and nothing else. A geotechnical
report is authoritative for ground conditions and groundwater. A design
calculation is authoritative for the adopted structural scheme and its
parameters. Drawings are authoritative for geometry, arrangement, and detailing.

Where two sources speak to the same quantity, note which one is closer to the
decision and record the disagreement rather than silently preferring one.

## 2. Do not treat a format as closed until you have tried to open it

A binary CAD file is not an image. It is a structured database of entities with
coordinates, layers, and text, and it converts to a readable interchange format.
A large report is not a scan merely because it is large; check whether it has a
text layer before deciding to skip it.

The failure mode this guards against is silent: a source that cannot be opened
produces no error, it just never appears in the evidence trail, and the
deliverable then rests on whichever source happened to be convenient. If a
source really is unreadable, that is itself a finding worth recording — not a
reason to proceed as if it did not exist.

[Format access notes](references/format-access.md) records how to open each of
the source types used here, and the specific traps in each one.

## 3. Know where a document keeps its values

Engineering documents put their numbers in structurally different places, and
reading the wrong part returns headings instead of data.

- A calculation report generated by design software usually prints section
  headings as running text and puts every actual value in tables. Reading only
  the narrative returns a list of labels — scheme, basic information, surcharge,
  soil layers, soil parameters, design results, stability checks — with no
  numbers attached. The values live in the tables between those headings.
- Such a report repeats the same block structure once per analysed cross
  section. Establish which section a table belongs to before taking a number
  from it; adjacent blocks look identical and belong to different sections.
- A drawing keeps annotation text, dimension values, and layer names as separate
  entity kinds. Notes and design statements are usually long formatted text;
  dimensions carry their measured value as an attribute rather than as visible
  text.
- An investigation report keeps its summary parameters in tables and its
  borehole records as figures. Figures at the end of such reports frequently
  carry no text layer at all.

## 4. Make the locator at the moment you take the fact

Write the citation when the value is read, not afterwards from memory. A
reconstructed citation is where fabricated references come from: the file name
is right, the page or detail number is a guess, and nobody notices until a
reviewer tries to follow it.

A locator has to let a reviewer land on the same place: the file plus the page,
the table, the clause, the drawing detail, the grid axis, or the section mark.
A file name on its own is not a locator — it names the haystack.

Prefer the most specific level the source supports. A calculation report cites
better by section and table than by page. A drawing cites better by detail or
axis than by sheet.

## 5. Distinguish what the source states from what you derived

Keep four states apart as you extract, because they behave differently later:

- a value the source states directly;
- a value that follows from stated inputs by a calculation you can reproduce;
- a value resting on an assumption you introduced, which a reviewer may reject;
- a value the available evidence cannot support at all.

An absent value is not zero. A dash, a blank, and `NA` in a parameter table mean
the parameter was not applicable or not determined — recording any of them as a
number silently invents design input. Likewise, a value carried over from an
earlier revision is not a current value; check the revision the drawing or
calculation belongs to before adopting its geometry.

## 6. Carry the fact and its locator together

An evidence trail that exists only in working notes does not reach the reviewer.
Keep the locator attached to the value from the moment of extraction through
every intermediate calculation and into the delivered row. The common loss point
is an intermediate spreadsheet or script that keeps the number and drops the
reference; by the time the deliverable is assembled the origin has to be guessed.

Before finishing, sample a few delivered facts and follow each one back to its
source. If the trail cannot be walked in the direction a reviewer would walk it,
it is not yet an evidence trail.
