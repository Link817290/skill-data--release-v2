# Format access notes

Practical notes on opening the source formats an engineering package arrives in.
Each entry records what works, and the failure that is easy to mistake for
"there is nothing here".

## CAD drawings (`.dwg`)

A `.dwg` is a binary database, not a picture. Convert it to the DXF interchange
format first, then read the DXF with a CAD library.

```bash
dwg2dxf -o plan.dxf "环境平面图.dwg"
```

```python
import ezdxf
doc = ezdxf.readfile("plan.dxf")
msp = doc.modelspace()
```

Traps:

- **The converter refuses to overwrite an existing output file.** Converting a
  second drawing onto the same output path fails while the first conversion
  looks fine. Give each drawing its own output name, or delete the target first.
  The failure is a non-zero exit with no useful message.
- **Conversion back to DWG corrupts non-ASCII text.** A round trip through DWG
  leaves entity counts unchanged and the Chinese annotations mangled, so an
  entity-count check will not catch it. Convert one way only.
- **Rendering a drawing to an image discards annotation.** Renderers commonly
  drop formatted text and leader entities, producing a picture that looks
  unlabelled while the labels are present in the data. Read the entities; do not
  rasterise the drawing to read its notes.

What the entities hold:

| Entity | Carries |
| --- | --- |
| `TEXT` | single-line annotation, in `dxf.text` |
| `MTEXT` | paragraph annotation including design notes, in `.text` |
| `DIMENSION` | the measured value as an attribute, often not as visible text |
| `LWPOLYLINE`, `LINE` | geometry; coordinates give lengths and enclosed areas |
| `INSERT` | a block reference; repeated details and symbols |
| `HATCH` | fill regions, often material or ground indication |
| `MULTILEADER` | a note bound to a location on the drawing |

Formatted text carries inline control codes: `\W` scales width, `\P` is a
paragraph break, `\L` underlines, `\U+XXXX` encodes a character, and `%%D` is a
degree sign. Strip or translate these before matching text, or a note reading
`{\W0.65;\L1-1剖面图}` will not match a search for `1-1剖面图`.

Layer names are evidence in their own right. They frequently separate structural
elements, dimensions, annotation, and background survey, and give a fast way to
ask what element families the drawing actually contains.

## Design calculation reports (`.docx`)

Generated by structural design software. Read with a document library:

```python
import docx
doc = docx.Document("计算书.docx")
paragraphs = [p.text for p in doc.paragraphs]
tables = doc.tables
```

The critical fact: **the paragraphs hold headings, the tables hold values.**
Extracting only paragraph text returns bracketed section labels with no numbers.
A report of this kind commonly contains a few hundred tables.

The report repeats one block per analysed cross section, typically: scheme,
basic information, surcharge, soil-layer information, soil parameters, earth
pressure model, working conditions, design parameters, structural analysis,
section analysis, and the stability checks. The first table of a block usually
carries the governing facts — design grade, excavation depth, embedment depth,
analysis method and model.

Because every section repeats the same headings, a table is only interpretable
together with the section it sits under. Track the current section while walking
the document body in order; a table pulled out by index alone has no identity.

Note that a document library exposes paragraphs and tables as separate
sequences, which loses their interleaved order. To keep section context, walk
the underlying body elements in document order instead.

## Investigation reports (`.pdf`)

Check for a text layer before deciding anything:

```bash
pdftotext -layout 初步勘察.pdf - | head
```

A report can be image-heavy and still be fully readable: each page may carry a
scanned background image with a text layer on top. Measure per-page text length
rather than judging by file size. Pages with essentially no extractable text are
usually the figures — borehole logs, cross sections, plans — and are typically
grouped at the end.

Cite these by page, and where the report numbers its own sections or tables,
prefer that.

## Scope notes (`.md`)

Plain text, but the highest-stakes source in the package: it fixes contract
boundaries. Take the section labels from it verbatim, character for character.
Never abbreviate, translate, re-order the words, or replace a compound label
with one of its parts. A boundary label is a contractual identifier, not a
description.
