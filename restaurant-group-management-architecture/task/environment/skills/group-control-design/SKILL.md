# Group control system design

A control system chapter is a set of allocations that executives will apply. Every sentence should
state an allocation, the condition that bounds it, or the structural consequence of a variant. Do not
restate settled conclusions, schedules or department charters that the inputs already contain; point to
them in one clause if a decision depends on them.

Before you open any input, read the three references in full:
`references/decision-allocation.md`, `references/target-cascade.md` and
`references/long-term-variants.md`. Then work through the four passes below in order.

## Pass 1: fix the control facts you must obey

From the settled work, record for each layer and each industry: the layer's control type, which
industries it controls directly and in which mode, which industries it has delegated and to whom, which
units each node manages directly, and which nodes are virtual (no departments of their own). A single
layer can hold different modes for different industries; record the mode per industry, not per layer.
These notes drive every later pass. Do not rewrite a settled control type in the deliverable.

## Pass 2: build the decision grid, then allocate

List the strategic decisions as a grid before allocating anything: for every level of scope (the whole
group, each listed or holding platform, each industry, each set of businesses that one unit manages
together, each operating unit) and every decision family (portfolio, development, competition, investment
and financing), decide whether the decision exists. A set managed together is its own scope because the
unit that manages it allocates attention and capital across the set; when no unit manages businesses as a
set, there is no such row.
Split a family when the settled work treats units differently, for example core units that senior
executives run personally versus ordinary units. Then give each decision its roles: who drafts, who
reviews on the way up, who makes the final decision. Apply `references/decision-allocation.md`.

Allocate investment and asset-change approval separately from strategy, and state what decides which
layer approves (amount, nature, strategic weight). Never give final approval of investments to a node
the settled work limits to professional review. Do not invent amounts; if a threshold is needed and the
inputs give none, mark it as to be set and name who sets it.

## Pass 3: target and budget issuing

Write one issuer-to-receiver line for every management node that holds targets. Follow management
relationships, not equity. Apply `references/target-cascade.md`.

## Pass 4: long-term variants

For each variant the settled work leaves open, derive the business shape first, then the management
architecture: levels of control, which business units exist and whether each is an entity or virtual,
where functions sit, what happens to units the group still holds directly, and where unrelated holdings
go. State each difference from the near-term architecture as a decision. Apply
`references/long-term-variants.md`.

## Self-check before delivering

Answer each with a count or yes or no, and fix the grid or the tree rather than the summary.

1. Every industry the grid treats as its own scope has a development decision and a competition decision
   with a final approver, every set managed together has its set-level decisions (businesses inside the set
   are covered by those plus their own competitive decisions), and the grid has at least one unit-level competition
   decision per business unit that manages units.
2. For every decision, the final approver is the layer whose control mode over that industry matches the
   decision family (see the reference), and no layer approves a decision it has delegated away.
3. Every decision with a draft layer two or more levels below the approver has a stated review step or
   a reason why none is needed.
4. Every node that manages units appears once as an issuer, including virtual nodes, unless the settled
   work assigns issuing for its units to another node and the chapter names that issuer; no issuer sends
   targets to a unit whose management relationship sits elsewhere.
5. In each variant, the stated number of control levels agrees with which business units are entities.
6. Every unit the group holds directly today has a stated destination in each variant.
7. The chapter contains no restated upstream content, schedules or charters, and its length is close to
   the number of decisions it states, not to the length of the inputs.
