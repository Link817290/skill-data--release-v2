# Event Operations

Use this method when a real event brief specifies activities but leaves the operating relationships to the coordinator. It does not authorize changes to an approved program or create missing resources.

## Build the operating model

Read the brief and resource records separately. Record confirmed activity, date, zone, admission condition and resource facts, distinguishing a total pool from repeated mentions of the same pool. Identify which facts are fixed and which arrangements remain proposals. Preserve source conflicts for decision rather than silently combining incompatible versions.

Turn each activity into a dependency chain: prerequisites, opening checks, participant entry, supervised operation, exit and reset. A duty is executable when a responsible role, trigger, action and completion condition are all identifiable. Exact lead times must come from a source or remain proposed, not become invented policy.

For simultaneous zones or shared personnel, consult [staffing-and-flow](references/staffing-and-flow.md). For weather exposure, tools, participant vulnerability or missing critical personnel, consult [safety-and-recovery](references/safety-and-recovery.md). Use the relevant branch, not an indiscriminate list of all possible hazards.

## Close the plan

Check that one person's overlapping assignments are actually compatible, that entry controls enforce the approved slot and capacity, and that cleanup is finished before the next group arrives. Separate consumables, gifts and participant slots; quantities with different units cannot substitute for one another.

Define handoffs for issue decisions, materials and media. A closeout action needs a recipient or reconciliation purpose, not only an instruction to collect everything. Preserve proposed versus approved status through the final document. Keep the arrangement flexible when several professionally valid methods achieve the same operational result.

## Failure and stop conditions

Do not invent contact details, venues, personnel pools, approvals or confirmed contingency assets. Do not convert a hypothetical risk into an actual incident. When a missing fact blocks safe operation, identify the question, responsible decision maker and affected activity; do not conceal it with a confident-looking schedule. If the approved program is internally inconsistent, state the conflict and the decision needed before that dependency can be fixed.
