# Revenue-recognition policy review

This package evaluates an audit manager's ability to close a longitudinal revenue-recognition review across regulatory correspondence, registration filings, and two later annual reports. The deliverable is an issue ledger that must resolve contradictory versions, preserve genuine uncertainty, distinguish dated control-assurance states, and connect estimate changes to revenue and related costs.

The task is offline and text-first. Original HTML filings and a searchable PDF are placed in the workspace; the container includes a PDF text utility. The same program scorer with source-bound semantic adjudication is used for both runtime conditions and reads only the submitted ledger plus hidden scoring data.

The strict score measures thirty expert-anchored findings. The lenient score measures whether a usable, traceable review ledger was delivered and whether at least 12 issue judgments clear a substantive `0.50` evidence-state floor. That floor reuses strict issue evidence, so lenient is not independent. Both golden scores are 1.0000; `reward` aliases the strict score.

Result-score semantic checks use evaluator-side `LLM_JUDGE_BASE_URL`, `LLM_JUDGE_MODEL` (the release default is `gpt-5.6-sol`) and `LLM_JUDGE_API_KEY`. Configure these outside the package for new submissions. The package contains an exact-request Golden replay for both semantic stages; it is bound to the request and scorer runtime hashes and therefore applies only to the unchanged Golden. A different deliverable misses that replay and is judged live. Set `LLM_JUDGE_MODE` to `fresh`, `replay`, or `auto` (the default). The judge handles relation, evidence-state, citation, residual-evidence, and assertion-specific procedure equivalence in context; deterministic checks are limited to file readability, supplied-source hashes, and ledger shape. Required service failures abort scoring without score artifacts. Agent workspace/network permissions are unchanged.
